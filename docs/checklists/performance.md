# アプリ性能と起動時間

**項目No.：021〜024**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## C021

**チェック項目 No.021**

起動時間、画面描画のジャンク、ANR／ハング、メモリ、電池消費などアプリの主要な性能指標を、リリースごとまたは週1回以上の頻度で自動的に計測している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

コールドスタートの起動時間、主要画面のフレーム落ち、ハング、メモリ使用量、電池消費を、リリース候補ごとと毎週の定期実行でCIから自動計測しています。計測は iOS と Android の代表的な低性能端末と標準的な端末を固定して行い、データ量とネットワーク条件も揃えています。計測条件・ビルド番号・結果を保存し、前回から閾値を超えて悪化した指標はリリース判定の前に担当者が確認しています。

[原文の参照先](https://developer.apple.com/documentation/xcode/improving-your-app-s-performance)

## C022

**チェック項目 No.022**

性能指標とアプリサイズの計測結果をチーム内で共有し、アクションプランを定期的（月ごと〜半年ごと）に検討している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

起動時間、フレーム落ち、ANR／ハング率などの性能指標と、ストア配布サイズ・インストール後サイズをダッシュボードで共有しています。月次の定例で目標値との差、サイズ増加の要因となった依存ライブラリや画像・フォントなどの資産を確認し、利用者への影響が大きい項目から改善計画を作成しています。改善項目には担当者と完了条件を定め、次のリリース後の計測で効果を確認しています。

[原文の参照先](https://developer.android.com/topic/performance/vitals)

## C023

**チェック項目 No.023**

本番利用者の端末から収集する性能データ（Android vitals、MetricKit、クラッシュ・性能監視サービス等）で、OSバージョン・端末別の指標を常時計測している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

Android vitals、MetricKit、性能監視サービスから本番利用者の性能データを継続的に収集し、アプリバージョン・OSバージョン・端末機種ごとに起動時間、ハング、ANR、メモリ不足による終了を確認できます。段階的公開の期間中は新旧バージョンの指標を比較しています。データの送信停止や収集件数の急減も検知し、計測が継続していることを週次で確認しています。

[原文の参照先](https://developer.apple.com/documentation/metrickit)

## C024

**チェック項目 No.024**

目標やアラートを設定していないことによって、過度に最適化したり、OS更新や新端末で生じた性能劣化を見過ごしたりしてしまっている。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

起動時間、ANR率、ハング率などに目標値を定め、ストアが示す不良の基準も参考に悪化を検知するアラートを設定しています。改善は目標との差と影響を受ける利用者数で優先順位を決め、目標を満たす指標には追加の最適化を行っていません。OS の新バージョン公開時と主要な新端末の発売時には、端末・OS別の指標を担当者が確認し、アラートの対応者・調査手順・対応期限と対応結果を記録しています。

[原文の参照先](https://developer.android.com/topic/performance/vitals/launch-time)
