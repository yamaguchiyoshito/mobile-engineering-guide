# 依存ライブラリの管理

**項目No.：053〜056**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## C053

**チェック項目 No.053**

DependabotやRenovateなど依存ライブラリの更新を検知する仕組みを導入している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

Renovate を導入し、npm パッケージ、CocoaPods、Swift Package Manager、Gradle の依存ライブラリについて新しいバージョンを自動検知し、更新内容を PR で確認できるようにしています。実行頻度と対象リポジトリを定め、設定の停止や更新漏れも確認しています。PR には変更履歴へのリンクを含め、互換性や最低 OS バージョンへの影響を調査できるようにしています。

[原文の参照先](https://dxcriteria.cto-a.org/c9255445e39f4102ae1961a3b046a8e6)

## C054

**チェック項目 No.054**

依存ライブラリについて更新や置き換え、削除などの管理を定期的（月ごと〜半年ごと）に計画、実施できている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

月次で依存ライブラリを棚卸しし、更新、置き換え、削除の計画を作成しています。メンテナンス状況、セキュリティ、利用箇所、新しい OS や React Native への対応状況、アプリサイズへの影響を確認して優先順位を決めています。担当者と期限を設定し、iOS と Android の両方での動作確認と、不要な依存関係の削除まで追跡しています。

[原文の参照先](https://dxcriteria.cto-a.org/b70b47ffa2634bce85a887d8a46703ed)

## C055

**チェック項目 No.055**

依存ライブラリの重要度や自チームのリソースを踏まえて、更新の反映サイクルなどをポリシーとして定めている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

依存ライブラリを重要度と変更リスクで分類し、緊急更新は随時、通常更新は月次、React Native 本体やネイティブ SDK のメジャー更新は四半期ごとの計画で扱う方針を定めています。対応期限、必要な検証（対象端末・OS バージョンでの確認を含む）、担当者、自動マージを許可する条件を明文化しています。ストアの要件変更に伴う更新期限も方針に含め、保守工数を開発計画に組み込んで実施状況を確認しています。

[原文の参照先](https://dxcriteria.cto-a.org/0c9d0dc09aa74c909874bf0b0ec3ae29)

## C056

**チェック項目 No.056**

自動的に作成された依存ライブラリの更新Pull Requestが手つかずのまま形骸化してしまっている。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

自動作成された更新 PR を週次で確認し、担当者、対応期限、適用・保留・却下の判断を記録しています。ネイティブモジュールを含む更新では iOS と Android のビルドと起動確認を CI で自動実行し、判断に必要な材料をそろえています。保留には理由と再確認日を設定し、大量の PR が処理を妨げる場合は更新のグループ化や生成頻度を見直して、手つかずの状態を放置していません。

[原文の参照先](https://dxcriteria.cto-a.org/60ddfb9cc3f5409792e00fcebeeb5734)
