# UI部品と画面設計の再利用

**項目No.：009〜012**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## この分野の背景

この分野では、ボタンや入力欄などの画面の部品を共通化し、どの画面でも同じ見た目と動きで再利用できるようにする取り組みを扱います。ブラウザ上で動くWebの画面と違い、モバイルアプリはiOSとAndroidで戻る操作やキーボードの出方などの慣習が異なります。さらに、文字サイズ設定、ダークモード、画面読み上げなど端末側の設定によって表示が変わるため、部品ごとに確認しておかないと画面ごとに挙動がばらつきます。まず、共通部品の一覧（カタログ）があり、部品単体の表示をプレビューで確認できるかを確認してください。

分からない用語は[用語集](../guide/glossary.md)で確認できます。

## C009

**チェック項目 No.009**

デザインシステムに基づく共通UI部品（ネイティブ／React Nativeの部品）がカタログ化されており、それに該当しない部品も定期的（月ごと〜半年ごと）に整理し、改善している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

デザインシステムに基づく共通UI部品をカタログ化し、用途・入力項目・表示状態・ダークモードや文字サイズ変更時の表示・使用例を参照できるようにしています。デザインシステムの部品定義とiOS・Androidのコード上の部品の対応表を、デザイナーと共同で管理しています。四半期ごとに、画面固有の部品も含めて重複・未使用・共通化候補を棚卸ししています。統合や廃止は利用箇所と移行方法を確認し、ストアリリースの予定に合わせて実施しています。

[原文の参照先](https://m3.material.io/)

## C010

**チェック項目 No.010**

UI部品の責務、再利用性、状態の受け渡し、アクセシビリティ属性に関するチーム内プラクティスを逐次共有し、定期的（月ごと〜半年ごと）に見直して改善している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

UI部品の責務、状態を保持する位置と受け渡しの方法、再利用の判断基準、VoiceOver（iOSの画面読み上げ機能）・TalkBack（Androidの画面読み上げ機能）向けのラベルや役割などのアクセシビリティ属性の設定方針を文書化しています。PRレビューで得た知見を随時追記し、iOS・Androidそれぞれの実装例とともに共有しています。四半期ごとに実装とのずれを確認し、方針と部品を更新しています。

[原文の参照先](https://developer.apple.com/design/human-interface-guidelines)

## C011

**チェック項目 No.011**

宣言的UIフレームワーク（SwiftUI、Jetpack Compose、React Nativeなど）またはプラットフォーム標準の部品を基盤とし、プレビューやカタログ画面で部品単体の表示を確認できている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

iOSはSwiftUI（iOSの宣言的UIフレームワーク）、AndroidはJetpack Compose（Androidの宣言的UIフレームワーク）を基盤とし、既存の画面は改修の機会に合わせて段階的に移行しています。各部品にプレビューを用意し、ライト・ダーク表示、文字サイズ、長い文言、読み込み中・エラーなどの状態を部品単体で確認しています。デバッグビルドには部品のカタログ画面を設け、実機でも表示と操作を確認できます。採用フレームワークと基本的な実装方法を開発ガイドに記載しています。

[原文の参照先](https://developer.android.com/develop/ui/compose/documentation)

## C012

**チェック項目 No.012**

UI部品の設計パターンが開発者間で共有されておらず、部品の粒度（細かすぎ、大きすぎ）やiOS／Android間の挙動差をコントロールできていない。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

UI部品の設計パターンをチームで共有しており、粒度やプラットフォームごとの挙動を各開発者の判断だけに任せていません。責務、変更理由、再利用範囲、テストのしやすさを基準に分割・統合をレビューしています。戻る操作、キーボード表示、スクロール時の挙動などのiOS／Android間の差異は、各OSの慣習に合わせる箇所と統一する箇所を部品ごとに記録しています。過度に細分化された部品や責務が集中した部品は、改善対象として管理しています。

[原文の参照先](https://reactnative.dev/docs/components-and-apis)
