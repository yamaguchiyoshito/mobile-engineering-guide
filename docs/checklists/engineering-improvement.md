# 横断的な生産性向上と技術方針

**項目No.：085〜088**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## C085

**チェック項目 No.085**

横断的な技術向上を図るチームや取り組みがある場合、ユーザー体験や生産性の向上など事業成果に繋がる指標を追跡している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

横断施策ごとに、クラッシュフリー率、アプリの起動時間、ストア評価、リリース頻度、変更のリードタイム、手戻り工数など、事業成果につながる指標を設定しています。導入前後を比較する際は対象 OS バージョン、端末構成、機能の規模の違いを確認し、導入・運用・学習コストも含めて評価しています。月次で効果を追跡し、継続・改善・終了を判断しています。

[原文の参照先](https://dxcriteria.cto-a.org/cc2f745eb7f244dc962ac0a42eb9ed11)

## C086

**チェック項目 No.086**

チームの生産性を向上するためのツールやプラクティスをおおよそ定期的（月ごと〜半年ごと）に調査して導入を検討、試行している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

四半期ごとに、ビルド時間、テスト実行、署名とストア提出、実機での検証などのボトルネックを起点としてツールやプラクティスを調査しています。一部のアプリで小規模に試行し、作業時間、品質、保守負担、費用を比較した結果に基づいて導入を判断しています。採用後は手順と支援体制を整え、Xcode や Android Studio の更新後も効果が継続しているか確認しています。

[原文の参照先](https://dxcriteria.cto-a.org/9a2a833a3dea4211813edbddfebbef10)

## C087

**チェック項目 No.087**

チーム内やチーム間で共有すべき取り決めやナレッジをコンテンツ化して蓄積している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

アーキテクチャ方針、証明書とプロビジョニングの管理手順、ストア公開手順、OS 更新への追従手順、設計判断、障害事例を検索可能な場所に蓄積しています。文書には対象読者、対象プラットフォーム、管理者、最終更新日を記載しています。実装や運用の変更時に更新し、四半期ごとに古い情報と重複を整理しています。

[原文の参照先](https://dxcriteria.cto-a.org/bb5d39452e1149efbda798b4dca685aa)

## C088

**チェック項目 No.088**

組織内の技術方針が定まっておらず、なし崩し的に採用技術の断片化が進んでいる。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

iOS・Android の技術選定について、標準とする言語と UI フレームワーク、React Native などクロスプラットフォーム技術の採用条件、例外を認める条件、判断責任者を組織の技術方針として定めています。各アプリの採用技術と最低対応 OS バージョンを台帳で把握し、四半期ごとに差異と理由を確認しています。合理的な違いは認めつつ、理由のない重複導入や保守不能な分散には共通化・移行の計画を立てています。

[原文の参照先](https://dxcriteria.cto-a.org/23a2052725d4470cadde5fe336825390)
