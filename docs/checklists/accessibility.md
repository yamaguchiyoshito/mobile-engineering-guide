# モバイルアクセシビリティ

**項目No.：025〜028**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## この分野の背景

この分野では、目が見えにくい人や細かい操作が難しい人、大きな文字で使う人なども含め、誰もがアプリを操作できるようにする取り組みを扱います。モバイルアプリではOSに画面読み上げや文字サイズ変更などの機能が組み込まれており、Webのようにブラウザの仕組みに任せられない分、アプリ側で部品ごとにラベルや読み上げ順序を正しく設定する必要があります。独自の部品やスワイプなどのジェスチャ操作は、標準の部品に比べてこうした機能に対応しにくい点にも注意が必要です。まず、実機で画面読み上げ機能をオンにして、主要な操作を最後まで完了できるかを確認してください。

分からない用語は[用語集](../guide/glossary.md)で確認できます。

## C025

**チェック項目 No.025**

Accessibility Inspector、Accessibility Scanner、UIテストでのアクセシビリティ検査などを用いた自動または半自動の検査を日常的（日ごと〜週ごと）に実施している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

主要画面と共通UI部品に対するアクセシビリティ検査をUIテストに組み込み、PRごとと毎日の定期実行で動かしています。ラベルの欠落、タッチターゲットの大きさ、コントラスト、大きな文字サイズでの表示崩れを検査対象にしています。自動検査で扱えない画面は、週1回Accessibility Inspector（Xcodeのアクセシビリティ検査ツール） とAccessibility Scanner（Androidのアクセシビリティ検査アプリ） で担当者が確認し、必須基準への違反は修正してからマージしています。

[原文の参照先](https://developer.android.com/guide/topics/ui/accessibility/testing)

## C026

**チェック項目 No.026**

モバイルアプリで目指すアクセシビリティの品質基準（スクリーンリーダー対応、文字サイズ、コントラスト、タッチターゲット等）を開発ガイドラインとして定めている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

参照する規格の版と目標とする適合レベル、対象とするOSと支援技術をガイドラインに明記しています。スクリーンリーダーでのラベルと読み上げ順序、OSの文字サイズ設定への追従、コントラスト比、タッチターゲットの最小サイズ、動きを減らす設定への対応について、実装方法と確認方法を具体化しています。例外の扱いと受け入れ条件を定め、デザイン・実装・レビューで共通して使用しています。

[原文の参照先](https://www.w3.org/TR/WCAG22/)

## C027

**チェック項目 No.027**

開発プロセスの中で、スクリーンリーダー（VoiceOver／TalkBack）、拡大表示、キーボード・スイッチ操作などを用いた人によるレビューを行っている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

新しい画面の設計レビューとリリース前の確認に、人によるアクセシビリティレビューを組み込んでいます。実機でVoiceOver（iOSの画面読み上げ機能） とTalkBack（Androidの画面読み上げ機能） を使って主要な操作を完了できるかを確認し、拡大表示、最大の文字サイズ、外部キーボードやスイッチコントロール（外部スイッチで端末を操作する機能）での操作も確認しています。指摘はイシューとして記録し、修正後の再確認まで担当者を決めて追跡しています。

[原文の参照先](https://developer.apple.com/documentation/accessibility)

## C028

**チェック項目 No.028**

独自のUI部品やジェスチャ操作を開発する中で、プラットフォーム標準の読み上げ順序、フォーカス、操作性が失われてしまっている。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

独自のUI部品やジェスチャ操作を導入しても、スクリーンリーダーでの読み上げ順序、フォーカス移動、役割と状態の通知といった標準の操作性を損なっていません。可能な限りOS標準の部品を使用し、独自実装が必要な場合はアクセシビリティ要素の役割・ラベル・状態を設定しています。スワイプや長押しなどのジェスチャには、支援技術から実行できる代替操作を用意し、対応するOSバージョンのVoiceOverとTalkBackで動作を確認しています。

[原文の参照先](https://developer.android.com/guide/topics/ui/accessibility)
