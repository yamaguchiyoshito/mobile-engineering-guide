# デザインの一貫性とユーザーテスト

**項目No.：037〜040**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## この分野の背景

この分野では、色や余白、文字などの見た目の決まりをアプリ全体でそろえること、実際の利用者にアプリを使ってもらい使いにくい点を見つけること、デザインと開発の意思決定の進め方を扱います。モバイルアプリはスマートフォン、タブレット、折りたたみ端末など画面の大きさや形がさまざまで、iOSとAndroidで操作の慣習も異なるため、Webの画面より確認すべき表示の組み合わせが多くなります。また、リリース後の修正はストアの審査を経て配布されるため、Webのようにすぐに直すことが難しく、設計段階での確認が重要です。不慣れな方は、まず色や文字などの定義が一か所で管理され、iOSとAndroidで共通に使われているかを確認してください。

分からない用語は[用語集](../guide/glossary.md)で確認できます。

## C037

**チェック項目 No.037**

デザイントークン（視覚的な構成要素）やUIのバリエーション（状態の表現など）における一貫性を保つために、デザイナー等を含む関係者内で定期的（月ごと〜半年ごと）に棚卸しと整理を行っている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

色・余白・文字・角丸などのデザイントークンを iOS・Android・React Native で共通の定義から生成し、ダークモードや文字サイズ設定ごとの値も含めて管理しています。入力中・エラー・無効・読み込み中・オフラインなどのUI状態も共通部品として定義しています。デザイナーと開発者が四半期ごとに棚卸しし、重複・未使用・デザインと実装の不一致、OSごとの表現の差を整理しています。変更履歴、適用範囲、既存画面の移行方法を共有しています。

[原文の参照先](https://dxcriteria.cto-a.org/0ae07dc1a5484ab88fc19556efa0c7a9)

## C038

**チェック項目 No.038**

利用状況の把握や改善検討のために、実際の利用者を想定したユーザーテストを定期的（月ごと〜半年ごと）に実施している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

四半期ごとに、実際の利用者または利用状況が近い参加者を対象に、参加者が普段使う端末でアプリのユーザーテストを実施しています。初回起動、権限の許可、主要な利用シナリオについて、完了率・所要時間・迷いや誤操作を記録しています。課題に優先順位を付けて改善し、次のリリース後のテストと利用状況のデータで効果を確認しています。

[原文の参照先](https://dxcriteria.cto-a.org/207742747cc14f599e0ff8848b9c943a)

## C039

**チェック項目 No.039**

一般に公開されるURLはレスポンシブWebデザインを前提として利用デバイスの多様性に応えられるデザインと開発をしている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

アプリの画面は、小さな画面のスマートフォン、タブレット、折りたたみ端末の各画面サイズで主要な情報と操作を利用できるように設計しています。縦横の回転、分割表示、ノッチやホームインジケーター（iOSの画面下端に表示される横棒）などの安全領域、最大の文字サイズ設定での表示を確認しています。対応する画面サイズと OS バージョンの範囲を明記し、特定の端末で主要な操作が完了できなくなる状態を防いでいます。

[原文の参照先](https://dxcriteria.cto-a.org/535b09b0019740d18057aea266e5e6b7)

## C040

**チェック項目 No.040**

開発の意思決定フローの中で、デザインと実装どちらか片方だけの都合が優先されるようになってしまっている。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

設計上の意思決定にはデザインと開発の双方が参加し、利用者への価値、操作性、OS標準の操作との整合、実装・運用費用、ストア審査を含めた納期を共通の判断軸にしています。意見が分かれた場合は代替案や実機で動く試作を比較し、決定者と判断理由を記録しています。一方の都合だけで他方の要件を除外する運用にはしていません。

[原文の参照先](https://dxcriteria.cto-a.org/0cbc52118a334490b858a516c228dfc2)
