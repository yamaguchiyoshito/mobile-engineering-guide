# 端末・OS互換性とサポート方針

**項目No.：065〜068**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## C065

**チェック項目 No.065**

サポートする OS バージョン、端末、画面サイズ（タブレット・折りたたみ端末等）の方針を定め、利用者の分布データに基づいて定期的（半年ごと〜年ごと）に見直している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

サポートする最低 OS バージョン、対象端末、タブレットや折りたたみ端末での表示方針を文書にまとめ、アプリの設定値とストアの掲載情報に反映しています。半年ごとに、自社アプリの OS バージョン別・端末別の利用者分布と、プラットフォームが公開する普及率を確認し、見直しを判断しています。最低 OS バージョンを引き上げる場合は、影響する利用者数、告知の時期、旧バージョンのアプリの扱いを決めて記録しています。

[原文の参照先](https://developer.apple.com/support/app-store/)

## C066

**チェック項目 No.066**

OS のメジャーアップデートやベータ版に対して事前に動作確認と対応計画を行い、正式公開日までに互換性の問題を解消している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

iOS と Android のベータ版が公開されると、担当者が主要な画面と機能を検証し、動作の変更や非推奨になる API の影響を一覧にしています。影響ごとに対応方針、担当者、期限を決め、OS の正式公開日より前に対応版を審査へ提出する計画を立てています。正式公開後の1週間は、クラッシュ率とストアのレビューを OS バージョン別に確認し、見落とした問題を追加で修正しています。

[原文の参照先](https://developer.android.com/guide/practices/compatibility)

## C067

**チェック項目 No.067**

端末ファーム（Firebase Test Lab 等）や実機・シミュレータを組み合わせて、サポート対象の代表的な端末・OS バージョンで自動テストまたは手動確認を実施できている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

利用者の分布をもとに、OS バージョン、メーカー、画面サイズ、性能の異なる代表端末の組み合わせを定義しています。CI では Firebase Test Lab で代表端末に対する UI テストを夜間に実行し、審査提出前には手元の実機とシミュレータで手動確認を行っています。代表端末の一覧は半年ごとに見直し、社内に実機がない構成は端末ファームで補っています。

[原文の参照先](https://firebase.google.com/docs/test-lab)

## C068

**チェック項目 No.068**

サポート方針が曖昧なまま古い OS・端末への対応が残り続け、新しい API やライブラリを採用できず、不具合の切り分けにも時間がかかってしまっている。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

最低 OS バージョンと対象端末を方針として明文化し、引き上げの基準と手順を定めています。古い OS 向けの分岐や代替実装は一覧で管理し、最低バージョンを引き上げる際にまとめて削除しています。不具合の報告には OS バージョンと端末の情報を含めて記録し、サポート対象外の環境かどうかをすぐに判断できるため、切り分けに時間がかかる状態にはなっていません。

[原文の参照先](https://developer.android.com/guide/topics/manifest/uses-sdk-element)
