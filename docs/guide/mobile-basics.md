# モバイルアプリ開発の前提

このページは、モバイルアプリ開発に初めて関わる人が、本書のスキル定義とチェックリストを読む前に押さえておく前提をまとめたものです。Webやサーバーの開発経験がある人が戸惑いやすい点を中心に説明します。

## Webアプリとの違い

モバイルアプリは、利用者の端末にインストールされて動くプログラムです。サーバーで動くWebアプリと違い、配布の仕方、実行環境、利用者の環境の3点で前提が変わります。

| 観点 | Webアプリ | モバイルアプリ |
| :--- | :--- | :--- |
| 配布 | サーバーへデプロイすれば全員に反映される。 | ストア（App Store、Google Play）の審査を経て配布する。利用者が更新するまで旧バージョンが端末に残る。 |
| 修正の到達 | 数分で全利用者に届く。 | 審査、段階的公開、利用者の更新操作を経るため、数日から数週間かかる。重大な不具合には緊急の審査申請や機能フラグで対処する。 |
| 実行環境 | ブラウザが吸収する。 | OSのバージョン、端末の性能、画面サイズ、メモリ、電池が多様である。古いOSのサポート範囲をチームで決める。 |
| 通信 | 常時接続を前提にできる。 | 移動中や電波の弱い場所でも使われる。通信の切断、遅延、再送を前提に設計する。 |
| データの保存 | 主にサーバー側。 | 端末内のアプリ専用領域（サンドボックス）に保存する。秘密情報は専用の保護領域に置く。 |
| 権限 | ブラウザが一括して扱う。 | 位置情報、カメラ、通知などをOSが管理し、利用者に許可を求める。拒否された場合の動作も実装する。 |
| ライフサイクル | ページの読み込みと離脱。 | 起動、前面、背面、中断、終了をOSが制御する。背面に回ったアプリはメモリ不足で終了されることがある。 |
| セキュリティ | サーバーで秘密を守れる。 | 配布したアプリは解析され得る。APIキーなどの秘密情報をアプリに埋め込めない。 |
| 監視 | サーバーのログで把握できる。 | クラッシュは端末上で起きる。収集サービスに送り、クラッシュ位置をソースに対応付けて分析する。 |

## 三つのプラットフォーム

本書はiOS、Android、React Nativeを対象とします。それぞれ言語、UIの作り方、配布先が異なります。

| 項目 | iOS | Android | React Native |
| :--- | :--- | :--- | :--- |
| 提供元 | Apple | Google | Meta（オープンソース） |
| 主な言語 | Swift | Kotlin | JavaScript／TypeScript |
| UIの作り方 | SwiftUI（宣言的）、UIKit（命令的） | Jetpack Compose（宣言的）、Views／XML（命令的） | Reactのコンポーネント。実行時にネイティブ部品を描画 |
| 開発環境 | Xcode（macOSが必要） | Android Studio（Windows、macOS、Linux） | エディタ＋Expo または各ネイティブ環境 |
| 配布先 | App Store、TestFlight | Google Play、内部テスト配布 | 両ストア |
| 本書のスキル | Swift、Swift並行処理、SwiftUI、UIKit | Kotlin、Kotlinコルーチン・Flow、Jetpack Compose、Android Views・Fragment | React Native実装、React Nativeのネイティブ連携 |

「宣言的UI」は、状態を書き換えると画面が自動的に追従する作り方です。「命令的UI」は、画面の部品を直接操作して更新する作り方です。近年の新規開発は宣言的UIが主流ですが、既存アプリの保守では命令的UIの知識も必要です。

React Nativeは、Webで使われるReactと同じコンポーネントの考え方で、iOSとAndroidの両方のアプリを一つのコードから作る方式です。HTMLとCSSではなく各OSのネイティブ部品を描画するため、見た目と動作はネイティブアプリに近くなります。プッシュ通知や端末機能の連携、性能問題の調査ではネイティブの知識が必要になります。

## 開発に必要な環境

| 必要なもの | 説明 |
| :--- | :--- |
| macOS上のXcode | iOSアプリのビルドと配布にはmacOSとXcodeが必須です。React NativeでiOS向けにビルドする場合も同じです。 |
| Android Studio | Androidアプリの開発環境です。Windows、macOS、Linuxで動きます。 |
| シミュレータ・エミュレータ | 端末がなくても動作を確認できます。ただし、カメラ、プッシュ通知、性能、電池の確認には実機が必要です。 |
| 実機と開発者アカウント | 実機での確認とストア配布には、Apple Developer ProgramとGoogle Play Consoleの登録が必要です。チームで管理する場合は権限を確認します。 |
| 署名鍵・証明書 | アプリの開発者を証明する資格情報です。紛失すると更新版を配布できなくなるため、保管と更新の手順をチームで決めます。 |
