# モバイルセキュリティ

**項目No.：029〜032**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## この分野の背景

この分野では、アプリや利用者のデータが不正に読み取られたり改ざんされたりしないように、端末内の保存、通信、依存ライブラリ、秘密情報の扱いを守る取り組みを扱います。モバイルアプリは利用者の端末にアプリ本体が丸ごと配布されるため、処理がサーバー内で完結するWebと違い、アプリに含めた情報は解析によって取り出される可能性があります。また、脆弱性を修正してもストアの審査を経て配布され、旧バージョンが端末に残り続けるため、修正の到達に時間がかかります。不慣れな方は、まずAPIキーや署名用の鍵などの秘密情報がリポジトリやアプリ本体に含まれていないかを確認してください。

分からない用語は[用語集](../guide/glossary.md)で確認できます。

## C029

**チェック項目 No.029**

OWASP MASVS などモバイル向けの基準に基づく検査（静的解析、依存関係の脆弱性検査、モバイル固有の設定検査）を Pull Request ごとに実行し、基準を満たさない変更が混入しない仕組みになっている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

PRごとに静的解析、依存関係の脆弱性検査、Info.plist（iOSアプリの設定ファイル） や AndroidManifest.xml（Androidアプリの設定ファイル） などの設定検査をCIで実行しています。検査項目は OWASP MASVS（モバイルアプリのセキュリティ検証基準） の該当要件に対応付け、重大度ごとの許容基準を定めています。必須基準に違反した場合や検査自体が失敗した場合はマージを停止し、誤検知や例外は理由・承認者・有効期限を記録して再評価まで追跡しています。

[原文の参照先](https://mas.owasp.org/MASTG/)

## C030

**チェック項目 No.030**

認証情報・トークンの保管（Keychain／Keystore）、通信の保護（ATS、Network Security Config、証明書検証）、端末上のデータ保護についての実装基準を定め、開発者向けの教育・研修で更新している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

認証トークンは Keychain（iOSの秘密情報用の保存領域） と Android Keystore（Androidの鍵の保存・管理機構） で保護して保存し、平文の設定ファイルやログに残さないことを実装基準に定めています。ATS（App Transport Security。iOSの通信保護の既定設定） と Network Security Config（Androidの通信保護の設定ファイル） の例外の扱い、証明書検証（接続先のサーバーが本物かを確かめる処理）を無効にしないこと、端末上のファイル保護とバックアップ対象の除外も基準に含めています。開発者の参加時と半年ごとに、脆弱な実装と修正方法を演習で確認する研修を実施し、実際の指摘や OS の仕様変更を教材と実装基準に反映しています。

[原文の参照先](https://developer.apple.com/documentation/security/keychain-services)

## C031

**チェック項目 No.031**

依存ライブラリ・SDK の脆弱性を検知する仕組みを利用して、緊急度に応じた期間内にアップデートを適用し、ストアへ再配布できている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

CocoaPods（iOSのライブラリ管理ツール）、Swift Package Manager（Swift標準のライブラリ管理ツール）、Gradle（Androidのビルドツール）、npm（JavaScriptのパッケージ管理ツール） で管理する依存ライブラリと組み込みSDKの脆弱性を継続的に検知しています。重大度、悪用の有無、アプリ内で該当機能を使っているかから緊急度を判断し、事前に定めた期限内に更新・動作検証・ストア審査への提出まで行っています。修正版がない場合はサーバー側の設定などで暫定対策を行い、利用者の端末に修正版が行き渡るまで最低サポートバージョンの引き上げも含めて担当者が追跡しています。

[原文の参照先](https://developer.android.com/privacy-and-security/security-tips)

## C032

**チェック項目 No.032**

APIキー、秘密鍵、署名用の資格情報などの機密情報が、アプリのバイナリ・JSバンドル・リポジトリに埋め込まれてしまっている。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

非公開のAPIキー、秘密鍵、署名用の証明書や鍵ストアのパスワードを、アプリのバイナリ、JSバンドル、リポジトリに含めていません。署名用の資格情報はCIのシークレット管理機構で保管し、権限を限定してビルド時にだけ渡しています。アプリには利用者の端末に配布されても問題のない識別子だけを含め、秘密を要する処理はサーバー側で行っています。コミットとCIで混入を検査し、検出時は削除に加えて失効・再発行と影響調査を行います。

[原文の参照先](https://mas.owasp.org/MASVS/)
