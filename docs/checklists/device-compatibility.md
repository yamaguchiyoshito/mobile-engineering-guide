# 端末・OS互換性とサポート方針

**項目No.：065〜068**

回答例は望ましい状態を示す架空の文面です。[判定方法](../guide/team-assessment.md)と[記録書式](../templates/team-assessment.md)を使い、実態と根拠を記録してください。

## この分野の背景

この分野は、アプリがどのOSバージョン・機種・画面サイズで動くことを保証するかを決め、OSの更新に合わせて動作を確認する取り組みです。Webではブラウザの違いを吸収しやすい一方、モバイルアプリは毎年のOSの大型更新や、メーカーごとに異なる多数のAndroid端末の影響を直接受けます。対象を広げすぎると確認と保守の負担が増え、狭めすぎると利用できない人が出るため、利用者のデータに基づいた判断が必要です。まず、アプリが対応する最も古いOSバージョンと、その決め方が文書になっているかを確認してください。

分からない用語は[用語集](../guide/glossary.md)で確認できます。

## C065

**チェック項目 No.065**

サポートするOSバージョン、端末、画面サイズ（タブレット・折りたたみ端末等）の方針を定め、利用者の分布データに基づいて定期的（半年ごと〜年ごと）に見直している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

サポートする最低OSバージョン（アプリが動作する最も古いOSの版）、対象端末、タブレットや折りたたみ端末での表示方針を文書にまとめ、アプリの設定値とストアの掲載情報に反映しています。半年ごとに、自社アプリのOSバージョン別・端末別の利用者分布と、プラットフォームが公開する普及率を確認し、見直しを判断しています。最低OSバージョンを引き上げる場合は、影響する利用者数、告知の時期、旧バージョンのアプリの扱いを決めて記録しています。

[原文の参照先](https://developer.apple.com/support/app-store/)

## C066

**チェック項目 No.066**

OSのメジャーアップデートやベータ版に対して事前に動作確認と対応計画を行い、正式公開日までに互換性の問題を解消している。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

iOSとAndroidのベータ版が公開されると、担当者が主要な画面と機能を検証し、動作の変更や非推奨（将来の廃止が予告された状態）になるAPIの影響を一覧にしています。影響ごとに対応方針、担当者、期限を決め、OSの正式公開日より前に対応版を審査へ提出する計画を立てています。正式公開後の1週間は、クラッシュ率（アプリが異常終了したセッションの割合）とストアのレビューをOSバージョン別に確認し、見落とした問題を追加で修正しています。

[原文の参照先](https://developer.android.com/guide/practices/compatibility)

## C067

**チェック項目 No.067**

端末ファーム（Firebase Test Lab等）や実機・シミュレータを組み合わせて、サポート対象の代表的な端末・OSバージョンで自動テストまたは手動確認を実施できている。

**望ましい原文への回答：TRUE**

原文にある取り組みを実施している状態を目指します。

### 望ましい回答例

利用者の分布をもとに、OSバージョン、メーカー、画面サイズ、性能の異なる代表端末の組み合わせを定義しています。CIではFirebase Test Lab（クラウド上の端末でテストを実行するサービス） で代表端末に対するUIテストを夜間に実行し、審査提出前には手元の実機とシミュレータで手動確認を行っています。代表端末の一覧は半年ごとに見直し、社内に実機がない構成は端末ファーム（多数の実機を遠隔で利用できる環境）で補っています。

[原文の参照先](https://firebase.google.com/docs/test-lab)

## C068

**チェック項目 No.068**

サポート方針が曖昧なまま古いOS・端末への対応が残り続け、新しいAPIやライブラリを採用できず、不具合の切り分けにも時間がかかってしまっている。

**望ましい原文への回答：FALSE**

原文にある問題が発生していない状態を目指します。

### 望ましい回答例

最低OSバージョンと対象端末を方針として明文化し、引き上げの基準と手順を定めています。古いOS向けの分岐や代替実装は一覧で管理し、最低バージョンを引き上げる際にまとめて削除しています。不具合の報告にはOSバージョンと端末の情報を含めて記録し、サポート対象外の環境かどうかをすぐに判断できるため、切り分けに時間がかかる状態にはなっていません。

[原文の参照先](https://developer.android.com/guide/topics/manifest/uses-sdk-element)
